# AI Job Agent — Requirements

## 1. Product Overview

AI Job Agent is an AI-native job discovery and application-assistance platform that helps candidates discover relevant jobs, evaluate fit, organize opportunities, and assist with application workflows while keeping the candidate in control of final submissions.

The frontend is a React + TypeScript + Vite SPA deployed on Cloudflare Pages. The backend is TypeScript + Hono running natively on Cloudflare Workers. The system runs on the Cloudflare free tier (Workers, Pages, D1, KV, R2, Queues, Workers AI, Vectorize) with Amazon Bedrock (Claude Opus) as the primary LLM provider.

## 2. Goals

- Discover relevant jobs from multiple sources.
- Normalize and deduplicate job listings.
- Match jobs against a candidate profile and preferences.
- Explain why a job is a good or poor fit.
- Track applications and application status.
- Use AI agents for research, ranking, extraction, and workflow assistance.
- Keep sensitive candidate data secure and minimize unnecessary storage.
- Provide an auditable record of agent actions and decisions.

## 3. Core Functional Requirements

### Job Discovery
- Support multiple job sources through APIs, feeds, permitted crawling, or user-provided sources.
- Search by role, skills, location, remote preference, experience, salary, employment type, and keywords.
- Store source URL, source name, job ID when available, timestamps, and listing metadata in D1.
- Detect duplicate and substantially identical listings.

### Candidate Profile
- Store structured profile information (skills, experience, education, preferred roles, locations, work preferences) in D1.
- Support resume ingestion: upload to R2, extract structured data via Workers AI, store extracted fields in D1.
- Allow users to review and edit extracted profile information.

### Job Matching
- Calculate a transparent relevance/fit score using Workers AI embeddings and Vectorize for semantic similarity.
- Consider required skills, preferred skills, experience, location, compensation, and user preferences.
- Surface missing requirements and potential concerns.
- Provide concise explanations for recommendations generated by Workers AI.

### AI Agent Workflow
- Research and discover jobs via Worker-based adapters.
- Extract and normalize job information using Claude Opus via Amazon Bedrock.
- Evaluate candidate-job fit using embeddings (Workers AI + Vectorize) and LLM reasoning (Bedrock Claude Opus).
- Rank opportunities.
- Generate application preparation suggestions.
- Draft application content when requested.
- Require explicit user approval before consequential external actions such as submitting an application.
- Cache all AI results in D1 or KV to avoid redundant LLM calls and Bedrock costs.

### Application Tracking
- Track saved, preparing, applied, interviewing, offer, rejected, withdrawn, and other configurable states in D1.
- Record application dates, source, notes, and relevant links.
- Provide a timeline of important application events.

### Notifications
- Notify users about high-quality matches and important application events.
- Avoid noisy or duplicate notifications.

## 4. Non-Functional Requirements

### Security
- Encrypt data in transit (HTTPS enforced by Cloudflare).
- Apply least-privilege access to Workers bindings (D1, KV, R2, Queues, AI).
- Never expose API keys or secrets to clients; store all secrets in Cloudflare Workers Secrets.
- Protect resumes and other personal data: R2 objects must not be publicly accessible; serve through authenticated Worker endpoints only.

### Privacy
- Collect only data required for product functionality.
- Provide clear data retention and deletion behavior.
- Do not share candidate information with third parties without appropriate user authorization.

### Reliability
- Job ingestion must be idempotent (deduplicate by source + job ID in D1 before inserting).
- Agent workflows must tolerate retries and partial failures.
- External provider failures must not corrupt application state.
- Cloudflare Queues on the free tier retains messages for 24 hours only. All ingestion and agent jobs pushed to a Queue must be consumed and completed within 24 hours or they are lost. Design jobs to be short, checkpointed, or re-triggerable.

### Observability
- Structured JSON logs emitted from every Worker; captured by Workers Logs (200,000 events/day, 3-day retention on free tier).
- Key metrics (ingestion count, match scores, Neuron usage, queue depth, failures) written to D1 or Cloudflare Analytics Engine.
- Agent runs stored in D1 with inputs, outputs, tool calls, and final status for auditability.

### Performance
- Fast interactive search and filtering: queries against D1 must be indexed appropriately to avoid full-table scans.
- Asynchronous processing for job ingestion, AI extraction, and matching via `waitUntil` — keep Worker request handlers within the 10 ms CPU limit.
- Workers AI is limited to 10,000 Neurons/day on the free tier. Expensive operations (resume extraction, bulk matching) must batch carefully, cache results, and avoid re-running inference on unchanged data.

## 5. Agent Safety and Control

- Agents must operate within explicitly defined Workers bindings and tool interfaces — no direct infrastructure access.
- External side effects (e.g., submitting an application to a job board) require explicit user authorization.
- Application submission must never happen silently.
- Agent actions are logged to D1 and observable via Workers Logs.
- Content scraped or crawled from job pages is treated as untrusted data; it is never injected directly into prompts without sanitization, to guard against prompt injection.

## 6. MVP Scope

1. User profile and resume ingestion (R2 for file, Workers AI for extraction, D1 for structured data).
2. Job discovery from an initial set of sources via Worker adapters.
3. Job normalization and deduplication in D1.
4. Candidate-job matching and ranking via Vectorize + Workers AI.
5. Saved jobs.
6. Application tracking in D1.
7. AI-assisted job analysis and application preparation via Workers AI.
8. Basic agent execution and audit trail stored in D1.

### Cloudflare Free-Tier Limits (design constraints)

| Service | Free Limit | Design Constraint |
|---|---|---|
| Workers | 100,000 requests/day, 10 ms CPU/invocation | Offload all heavy computation to Queue consumers; keep request handlers thin |
| D1 | 5 GB storage, 5 M rows read/day, 100,000 rows written/day | Index all frequently queried columns; batch writes; avoid read-heavy polling patterns |
| KV | 100,000 reads/day, 1,000 writes/day, 1 GB storage | Use for caching and config only; do not store primary application data |
| R2 | 10 GB storage/month, free egress | Resume and document storage is within limits at MVP scale; enforce file-size limits on uploads |
| Queues | 10,000 operations/day, 24-hour message retention | Keep daily job volume well below 10,000; all queued jobs must complete within 24 hours |
| Workers AI | 10,000 Neurons/day | Cache AI responses in D1/KV; batch embeddings; do not re-run inference on unchanged inputs |
| Vectorize | Included in free plan | Use for semantic job-candidate matching and RAG retrieval |

**No paid database or hosting services are used.** PostgreSQL, Neon, Supabase, Hyperdrive, and Cloudflare Containers are excluded — they are either paid-only or require external hosting. The stack runs on Cloudflare free-tier services plus Amazon Bedrock (pay-per-use LLM), Adzuna API (free tier, job search aggregator), and Apify (usage-based, premium Indeed scraping via `borderline~indeed-scraper`).

## 7. Future Scope

- Additional job providers.
- Personalized job-search agents.
- Automated recurring searches.
- Interview preparation.
- Application analytics.
- Advanced recommendation models.
- Human-in-the-loop application automation with explicit approvals.
- Upgrade to Workers Paid plan to unlock Containers, longer Queue retention (up to 14 days), higher AI Neuron quotas, and Hyperdrive for PostgreSQL connectivity.
